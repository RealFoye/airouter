## 1. 安装

### 前置条件

- Python 3.11+
- macOS / Linux（Windows 未测试）

### 安装步骤

```bash
# 克隆项目
git clone <repo-url>
cd airouter

# 创建虚拟环境
python -m venv .venv
source .venv/bin/activate

# 安装依赖（开发模式）
pip install -e ".[dev]"

# 验证安装
ai-router --help
```

安装成功后应看到 5 个子命令：`analyze`、`audit`、`benchmark`、`optimize`、`run`。

## 2. 配置 API Key

### 方式一：.env 文件（推荐）

在项目根目录创建 `.env` 文件：

```bash
AIROUTER_DASHSCOPE_API_KEY=sk-xxxx
AIROUTER_DEEPSEEK_API_KEY=sk-xxxx
AIROUTER_ZHIPU_API_KEY=sk-xxxx
AIROUTER_KIMI_API_KEY=sk-xxxx
AIROUTER_MINIMAX_API_KEY=sk-xxxx
```

**注意**：环境变量前缀是 `AIROUTER_`，字段名全大写。

### 方式二：环境变量

```bash
export AIROUTER_DEEPSEEK_API_KEY=sk-xxxx
```

### 哪些命令需要 API Key？

| 命令 | 需要 API Key | 说明 |
|------|:---:|------|
| `analyze` | 否 | 纯离线路由分析 |
| `optimize` | 否 | 纯离线 Prompt 分析 |
| `benchmark --level 1` | 否 | 离线规则评测 |
| `benchmark --level 2` | 视情况 | 默认 mock，加 `--real-api` 需 Key |
| `benchmark --level routing` | 视情况 | 同上 |
| `audit` | 否 | 查数据库 |
| `run --dry-run` | 否 | 只分析不执行 |
| `run --yes` | **是** | 真实调用模型 API |

## 3. 命令总览

```
ai-router <command> [options]

命令:
  analyze    分析任务并给出路由建议（零成本）
  optimize   分析 Prompt 并给出成本优化建议（零成本）
  benchmark  运行基准测试（L1 零成本）
  audit      消费审计与归因分析（零成本）
  run        启动 Agent 执行任务（可选 dry-run）
```

所有命令都支持 `--format rich|json` 切换输出格式。默认 `rich`（终端美化输出）。

## 4. analyze — 路由分析

**用途**：输入任务描述，系统分析应该用哪个模型、什么策略、预估成本多少。

**不消耗 API，纯离线分析。**

### 基本用法

```bash
ai-router analyze "写一个 FastAPI JWT 鉴权中间件"
```

### 参数

| 参数 | 说明 |
|------|------|
| `task` | （必填）任务描述文本 |
| `--format`, `-f` | 输出格式：`rich`（默认）或 `json` |
| `--show-complexity` | 显示 ML 复杂度分析详情 |

### 示例

```bash
# 基本分析
ai-router analyze "修复 auth.py 中的 SQL 注入漏洞"

# 查看 ML 复杂度详情
ai-router analyze "重构用户认证模块" --show-complexity

# JSON 输出（方便程序处理）
ai-router analyze "写单元测试" --format json
```

### 输出内容

- **任务特征**：类别（代码生成/重构/Bug修复等）、复杂度（SIMPLE/MODERATE/COMPLEX/EXPERT）、风险等级
- **推荐策略**：SINGLE_MODEL / PLAN_EXECUTE / PLAN_EXECUTE_REVIEW
- **推荐模型**：具体模型名 + 预估成本 + 基线成本 + 节省率
- **替代方案**：其他可选策略及对应模型
- **质量门禁**：是否需要人工审查

## 5. optimize — 成本优化

**用途**：分析一段 Prompt 的 Token 组成，给出省钱建议（缓存、压缩、模型降级、裁剪等）。

**不消耗 API，纯离线分析。**

### 基本用法

```bash
ai-router optimize --prompt "你的 prompt 内容..."
```

### 参数

| 参数 | 说明 |
|------|------|
| `--prompt`, `-p` | Prompt 文本（和 `--context-file` 至少提供一个） |
| `--context-file`, `-c` | 从文件读取 Prompt |
| `--model`, `-m` | 当前使用的模型名（可选，不提供则用路由推荐） |
| `--scenario`, `-s` | 使用场景，默认 `SINGLE_TURN` |
| `--turns`, `-t` | 预期对话轮数 |
| `--format`, `-f` | 输出格式 |

### 使用场景（scenario）

| 场景 | 说明 | 典型缓存率 |
|------|------|-----------|
| `SINGLE_TURN` | 单次对话 | 低 |
| `FIXED_PROMPT_TOOLS` | 固定 system prompt + 工具定义 | 高 |
| `AGENT_MULTI_TURN` | Agent 多轮对话 | 中高 |
| `SAME_PROJECT_REPEAT` | 同一项目重复任务 | 很高 |
| `RANDOM_CONTEXT` | 随机上下文 | 低 |

### 示例

```bash
# 直接传 prompt
ai-router optimize --prompt "你是一个代码审查专家..."

# 从文件读取
ai-router optimize --context-file my_prompt.txt

# 指定场景和轮数
ai-router optimize --prompt "..." --scenario AGENT_MULTI_TURN --turns 10

# 指定当前模型
ai-router optimize --prompt "..." --model deepseek-v4-pro
```

### 输出内容

- **输入组成分析**：System Prompt / 工具定义 / 项目上下文 / 对话历史 / 用户请求各占多少 Token
- **优化建议表**：每条建议的类别、描述、预估节省金额和比例
- **压缩策略对比**：保守/标准/激进三种压缩方案的效果对比
- **汇总**：合计可省多少钱

## 6. benchmark — 基准测试

**用途**：评测路由系统的准确率和模型质量。

### 参数（通用）

| 参数 | 说明 |
|------|------|
| `--level`, `-l` | （必填）评测级别：`1`、`2`、`3`、`finance`、`routing` |
| `--format`, `-f` | 输出格式 |

### Level 1：离线规则评测（零成本）

测试路由规则是否符合预期指标（准确率、覆盖率等）。

```bash
ai-router benchmark --level 1
```

| 参数 | 说明 |
|------|------|
| `--cases`, `-c` | 自定义 cases YAML 路径 |
| `--fail-fast` | 遇到第一个失败立即停止 |

**输出**：通过/失败 case 数、通过率、各指标达标情况。

### Level 2：模型质量评测

真实调用模型 API 对比输出质量。

```bash
# mock 模式（不消耗 API）
ai-router benchmark --level 2

# 真实 API 模式
ai-router benchmark --level 2 --real-api --models deepseek-v4-flash,minimax-m2.5

# 带 LLM Judge 评分
ai-router benchmark --level 2 --real-api --judge --judge-models qwen3.7-max
```

| 参数 | 说明 |
|------|------|
| `--models` | 逗号分隔的模型列表 |
| `--real-api` | 使用真实 API（默认 mock） |
| `--rate-limit` | 每分钟最大请求数（默认 20） |
| `--resume` | 从断点恢复 |
| `--run-id` | 恢复指定 run |
| `--limit` | 最大执行 pair 数 |
| `--workers` | 并发 worker 数（默认 5） |
| `--judge` | 运行 LLM Judge 评分 |
| `--judge-model` | Judge 模型列表 |
| `--judge-workers` | Judge 并发数（默认 20） |
| `--skip-pairwise` | 跳过成对比较 |

### Level 3：策略回测（零成本）

用历史数据回测路由策略的成本效果。

```bash
ai-router benchmark --level 3
ai-router benchmark --level 3 --case-set l1 --baseline-model qwen3.7-max
```

| 参数 | 说明 |
|------|------|
| `--case-set` | 数据集：`all`（默认）、`l1`、`l2` |
| `--baseline-model` | 基线模型（默认 `qwen3.7-max`） |

**输出**：总成本对比、节省率、策略分布、安全降级/风险降级案例。

### Finance：企业财务评测

```bash
ai-router benchmark --level finance --real-api
```

### Routing：路由 Ground Truth 评测

```bash
ai-router benchmark --level routing
ai-router benchmark --level routing --rerun   # 完整重跑
```

## 7. audit — 消费审计

**用途**：分析数据库中的消费记录，找出浪费模式和重度用户。

**不消耗 API，查询本地数据库。**

### 基本用法

```bash
ai-router audit
```

### 参数

| 参数 | 说明 |
|------|------|
| `--days`, `-d` | 审计时间范围（默认 30 天） |
| `--user` | 按用户过滤 |
| `--project` | 按项目过滤 |
| `--department` | 按部门过滤 |
| `--db` | 数据库 URL（默认 `sqlite:///seed.db`） |
| `--format`, `-f` | 输出格式 |

### 示例

```bash
# 默认审计最近 30 天
ai-router audit

# 审计指定用户
ai-router audit --user alice --days 7

# 审计指定部门
ai-router audit --department engineering --days 90

# JSON 输出
ai-router audit --format json
```

### 输出内容

- **汇总**：总成本、总调用次数、日均消费、总 Token 数
- **按用户/模型/项目/部门**：多维度的成本分布表
- **浪费模式**：Top 5 浪费模式及改进建议
- **重度用户**：消费超过总成本 30% 的用户

## 8. run — Agent 执行

**用途**：启动 Agent 自主完成开发任务（读文件、改文件、跑测试）。

### 基本用法

```bash
# 先 dry-run 看看分析结果
ai-router run "修复 auth.py 中的 SQL 注入漏洞" --workdir demo/scenario1-sql-inject --dry-run

# 确认没问题，真实执行
ai-router run "修复 auth.py 中的 SQL 注入漏洞" --workdir demo/scenario1-sql-inject --yes
```

### 参数

| 参数 | 说明 |
|------|------|
| `task` | （必填）任务描述 |
| `--workdir`, `-w` | 工作目录（默认当前目录） |
| `--dry-run` | 只分析不执行 |
| `--max-cost` | 成本上限，单位元（默认 1.0） |
| `--max-turns` | 最大工具调用轮数（默认 10） |
| `--yes`, `-y` | 跳过人工确认 |
| `--format`, `-f` | 输出格式 |

### 执行流程

1. **路由分析**：分析任务 → 选策略 → 选模型
2. **人工审批**（如果风险高且没加 `--yes`）：展示任务详情，等待 `y/N` 确认
3. **Agent 执行**：
   - 模型通过工具（read_file / write_file / edit_file / run_command）自主完成
   - 每轮：模型思考 → 调用工具 → 看结果 → 继续
   - 直到任务完成、成本超限、或达到最大轮次
4. **输出报告**：成本、Token 用量、节省率、工具调用历史

### 安全机制

- **路径沙箱**：文件操作不能超出 `--workdir` 目录
- **命令白名单**：只允许 pytest / ruff / git status / git log / git diff / ls / wc / head / tail
- **危险模式拦截**：rm -rf / sudo / chmod 777 / git push --force 等被拦截
- **成本上限**：超过 `--max-cost` 自动停止

### Agent 能用的工具

| 工具 | 说明 | 什么时候可用 |
|------|------|-------------|
| `read_file` | 读取文件 | 始终可用 |
| `edit_file` | 精确替换文本 | 始终可用 |
| `run_command` | 执行命令 | 始终可用（受白名单限制） |
| `write_file` | 创建/覆盖文件 | 代码生成/重构/测试生成任务 |

### 执行策略

| 策略 | 说明 | 何时触发 |
|------|------|---------|
| `SINGLE_MODEL` | 单模型独立完成 | 大多数任务（系统智能选择） |
| `PLAN_EXECUTE` | Planner 规划 + Executor 执行 | 复杂任务且 PE 成本更优时 |
| `PLAN_EXECUTE_REVIEW` | 上述 + Reviewer 审查 | 高风险复杂任务 |

## 9. Demo 演示流程

项目包含 4 个预置 demo 场景，在 `demo/` 目录下。

### 准备

```bash
# 恢复所有 demo 到初始状态
python demo/reset_scenarios.py
```

### 演示顺序（建议）

```bash
# 1. 路由分析（零成本）
ai-router analyze "写一个 FastAPI JWT 鉴权中间件"

# 2. 成本优化（零成本）
ai-router optimize --prompt "你是一个专业的代码审查专家，擅长发现安全漏洞和性能问题。请对以下代码进行审查，输出问题列表和修复建议。"

# 3. Benchmark（零成本）
ai-router benchmark --level 1

# 4. Agent dry-run（零成本）
ai-router run "修复 auth.py 中的 SQL 注入漏洞" --workdir demo/scenario1-sql-inject --dry-run

# 5. Agent 真实执行（需要 API Key）
ai-router run "修复 auth.py 中的 SQL 注入漏洞" --workdir demo/scenario1-sql-inject --yes

# 6. 执行完恢复
python demo/reset_scenarios.py
```

### Demo 场景列表

| 场景 | 目录 | 任务 |
|------|------|------|
| SQL 注入修复 | `demo/scenario1-sql-inject/` | 修复 auth.py 中的 SQL 注入漏洞 |
| 邮件验证器 | `demo/scenario2-email-validator/` | 实现邮件格式验证函数 |
| Bug 修复 | `demo/scenario3-bug-fix/` | 修复计算器的除法 bug |
| 认证重构 | `demo/scenario4-refactor-auth/` | 重构用户认证模块 |

## 10. 常见问题

### Q: 运行 `ai-router` 提示 command not found？

确保已安装并激活虚拟环境：

```bash
source .venv/bin/activate
pip install -e .
```

### Q: 运行 `run --yes` 报 API 错误？

检查 `.env` 文件是否存在且包含有效的 API Key。Key 格式：`AIROUTER_DEEPSEEK_API_KEY=sk-xxxx`。

### Q: sklearn 版本警告？

正常现象（OpenSquilla ML 模型的 pickle 版本差异），不影响功能。程序已自动静默该警告。

### Q: Agent 执行后文件没变化？

- 检查 `--workdir` 是否正确指向 demo 目录
- 检查工具调用历史中是否有 FAIL
- 某些模型（如 flash 版本）在输出大段代码时可能 JSON 格式出错

### Q: 为什么系统选择 SINGLE_MODEL 而不是 Plan-Execute？

这是智能路由的设计特性。系统会根据成本-质量评分选择最优策略。当 Tier 1 模型（如 deepseek-v4-pro）性价比足够高时，单模型反而比 Planner+Executor 组合更优。Plan-Execute 会在 Tier 1 模型更贵、任务更复杂时自动触发。

### Q: 一次 Agent 执行大概花多少钱？

典型 demo 场景约 ¥0.01-0.05。相比 Tier 1 基线模型，通常节省 80-95%。
