## 1. 安装

### 前置条件

- Python 3.11+
- macOS / Linux（Windows 未测试）

### 安装步骤

```bash
# 克隆项目
git clone <repo-url>
cd airouter

# 创建虚拟环境
python -m venv .venv
source .venv/bin/activate

# 安装开发与 OpenSquilla ML 依赖
pip install -e ".[dev,ml]"

# 验证安装
ai-router --help
```

安装成功后应看到 6 个子命令：`analyze`、`audit`、`benchmark`、`optimize`、`run`、`agent`。

> `run` 和 `agent` 会使用 OpenSquilla `ml_final` 复杂度结果。若未安装 `ml` 依赖，复杂度分析会回退到 Rules，因此正式演示必须安装 `.[dev,ml]`。

## 2. 配置 API Key

### 方式一：.env 文件（推荐）

在项目根目录创建 `.env` 文件：

```bash
AIROUTER_DASHSCOPE_API_KEY=sk-xxxx
AIROUTER_DEEPSEEK_API_KEY=sk-xxxx
AIROUTER_ZHIPU_API_KEY=sk-xxxx
AIROUTER_KIMI_API_KEY=sk-xxxx
AIROUTER_MINIMAX_API_KEY=sk-xxxx
```

**注意**：环境变量前缀是 `AIROUTER_`，字段名全大写。

### 方式二：环境变量

```bash
export AIROUTER_DEEPSEEK_API_KEY=sk-xxxx
```

### 哪些命令需要 API Key？

| 命令 | 需要 API Key | 说明 |
|------|:---:|------|
| `analyze` | 否 | 纯离线路由分析 |
| `optimize` | 否 | 纯离线 Prompt 分析 |
| `benchmark --level 1` | 否 | 离线规则评测 |
| `benchmark --level 2` | 视情况 | 默认 mock，加 `--real-api` 需 Key |
| `benchmark --level routing` | 视情况 | 同上 |
| `audit` | 否 | 查数据库 |
| `run --dry-run` | 否 | 只分析不执行 |
| `run --yes` | **是** | 真实调用模型 API |
| `agent` | **是** | 交互式多轮对话，真实调用模型 API |

## 3. 命令总览

```
ai-router <command> [options]

命令:
  analyze    分析任务并给出路由建议（零成本）
  optimize   分析 Prompt 并给出成本优化建议（零成本）
  benchmark  运行基准测试（L1 零成本）
  audit      消费审计与归因分析（零成本）
  run        单次 Agent 执行任务（可选 dry-run）
  agent      交互式 Agent 会话（多轮对话）
```

`analyze`/`optimize`/`benchmark --level 1`/`audit` 不需要 API Key。
`run`/`agent` 需要被选中模型所属提供商的 API Key（`--dry-run` 除外）。真实执行缺少 Key 时会明确报错，不会静默使用 Mock 结果。

## 4. analyze — 路由分析

**用途**：输入任务描述，系统分析应该用哪个模型、什么策略、预估成本多少。

**不消耗 API，默认使用本地 OpenSquilla `ml_final` 分析。ML 不可用时会提示并回退 Rules。**

### 基本用法

```bash
ai-router analyze "写一个 FastAPI JWT 鉴权中间件"
```

### 参数

| 参数 | 说明 |
|------|------|
| `task` | （必填）任务描述文本 |
| `--format`, `-f` | 输出格式：`rich`（默认）或 `json` |
| `--show-complexity` | 显示 ML 复杂度分析详情 |
| `--mode` | 复杂度模式：`opensquilla`（默认）、`rules`、`shadow` 或 `hybrid` |

### 示例

```bash
# 基本分析
ai-router analyze "修复 auth.py 中的 SQL 注入漏洞"

# 查看 ML 复杂度详情
ai-router analyze "重构用户认证模块" --show-complexity

# 与纯规则基线对照
ai-router analyze "重构用户认证模块" --mode rules --show-complexity

# JSON 输出（方便程序处理）
ai-router analyze "写单元测试" --format json
```

### 输出内容

- **任务特征**：类别（代码生成/重构/Bug修复等）、复杂度（SIMPLE/MODERATE/COMPLEX/EXPERT）、风险等级
- **推荐策略**：SINGLE_MODEL / PLAN_EXECUTE / PLAN_EXECUTE_REVIEW
- **推荐模型**：具体模型名 + 预估成本 + 基线成本 + 节省率
- **替代方案**：其他可选策略及对应模型
- **质量门禁**：是否需要人工审查

## 5. optimize — 成本优化

**用途**：分析一段 Prompt 的 Token 组成，给出省钱建议（缓存、压缩、模型降级、裁剪等）。

**不消耗 API，纯离线分析。**

### 基本用法

```bash
ai-router optimize --prompt "你的 prompt 内容..."
```

### 参数

| 参数 | 说明 |
|------|------|
| `--prompt`, `-p` | Prompt 文本（和 `--context-file` 至少提供一个） |
| `--context-file`, `-c` | 从文件读取 Prompt |
| `--model`, `-m` | 当前使用的模型名（可选，不提供则用路由推荐） |
| `--scenario`, `-s` | 使用场景，默认 `SINGLE_TURN` |
| `--turns`, `-t` | 预期对话轮数 |
| `--format`, `-f` | 输出格式 |

### 使用场景（scenario）

| 场景 | 说明 | 典型缓存率 |
|------|------|-----------|
| `SINGLE_TURN` | 单次对话 | 低 |
| `FIXED_PROMPT_TOOLS` | 固定 system prompt + 工具定义 | 高 |
| `AGENT_MULTI_TURN` | Agent 多轮对话 | 中高 |
| `SAME_PROJECT_REPEAT` | 同一项目重复任务 | 很高 |
| `RANDOM_CONTEXT` | 随机上下文 | 低 |

### 示例

```bash
# 1. 短 Prompt：验证命令可用。内容很短时没有优化建议是正常结果
ai-router optimize \
  --prompt "你是一个代码审查专家，请检查 SQL 注入和异常处理"

# 2. 分析已有长文件，并假设当前全程使用 qwen3.7-max
ai-router optimize \
  --context-file docs/CLI设计.md \
  --model qwen3.7-max

# 3. Agent 多轮场景：示例文件含超过 1024 tokens 的稳定前缀，可看到缓存建议
ai-router optimize \
  --context-file docs/examples/optimize-agent-context.txt \
  --scenario AGENT_MULTI_TURN \
  --turns 10 \
  --model qwen3.7-max

# 4. 保持其他输入相同，只替换当前模型，用于比较成本与降级空间
ai-router optimize \
  --context-file docs/examples/optimize-agent-context.txt \
  --scenario AGENT_MULTI_TURN \
  --turns 10 \
  --model deepseek-v4-pro

# 5. JSON 输出，适合脚本处理或精确查看字段
ai-router optimize \
  --context-file docs/examples/optimize-agent-context.txt \
  --scenario AGENT_MULTI_TURN \
  --turns 10 \
  --model qwen3.7-max \
  --format json
```

> `--scenario` 和 `--turns` 主要影响多轮 Prompt Caching 的收益估算，不会凭空让短 Prompt 产生优化空间。缓存建议还要求所选模型支持缓存，且 `System Prompt + Tool Definitions` 的稳定前缀至少达到该模型的最小长度；当前主要模型配置的阈值为 1024 tokens。

建议将文件按下面的标题分节，Token 组成会更准确：

```text
System Prompt:
...
Tool Definitions:
...
项目上下文:
...
对话历史:
用户：...
助手：...
当前请求:
...
```

### 输出内容

- **输入组成分析**：System Prompt / 工具定义 / 项目上下文 / 对话历史 / 用户请求各占多少 Token
- **优化建议表**：每条建议的类别、描述、预估节省金额和比例
- **裁剪依据**：若建议裁剪项目上下文，展示候选行号、原文片段、判定原因和预计减少 Token；除完全重复外均明确标为启发式候选，执行前需确认
- **压缩策略对比**：保守/标准/激进三种压缩方案的效果对比
- **汇总**：比较“当前模型缓存/内容精简”和“模型降级/Plan-Execute”两条路径，给出较优路径的参考节省；不会把不同模型路径的金额直接相加

## 6. benchmark — 基准测试

**用途**：评测路由系统的准确率和模型质量。

### 参数（通用）

| 参数 | 说明 |
|------|------|
| `--level`, `-l` | （必填）评测级别：`1`、`2`、`3`、`finance`、`routing` |
| `--format`, `-f` | 输出格式 |

### Level 1：离线规则评测（零成本）

测试路由规则是否符合预期指标（准确率、覆盖率等）。

```bash
ai-router benchmark --level 1
```

| 参数 | 说明 |
|------|------|
| `--cases`, `-c` | 自定义 cases YAML 路径 |
| `--fail-fast` | 遇到第一个失败立即停止 |

**输出**：通过/失败 case 数、通过率、各指标达标情况。

### Level 2：模型质量评测

真实调用模型 API 对比输出质量。

```bash
# mock 模式（不消耗 API）
ai-router benchmark --level 2

# 真实 API 模式
ai-router benchmark --level 2 --real-api --models deepseek-v4-flash,MiniMax-M3

# 带 LLM Judge 评分
ai-router benchmark --level 2 --real-api --judge --judge-models qwen3.7-max
```

| 参数 | 说明 |
|------|------|
| `--models` | 逗号分隔的模型列表 |
| `--real-api` | 使用真实 API（默认 mock） |
| `--rate-limit` | 每分钟最大请求数（默认 20） |
| `--resume` | 从断点恢复 |
| `--run-id` | 恢复指定 run |
| `--limit` | 最大执行 pair 数 |
| `--workers` | 并发 worker 数（默认 5） |
| `--judge` | 运行 LLM Judge 评分 |
| `--judge-model` | Judge 模型列表 |
| `--judge-workers` | Judge 并发数（默认 20） |
| `--skip-pairwise` | 跳过成对比较 |

### Level 3：策略回测（零成本）

用历史数据回测路由策略的成本效果。

```bash
ai-router benchmark --level 3
ai-router benchmark --level 3 --case-set l1 --baseline-model qwen3.7-max
```

| 参数 | 说明 |
|------|------|
| `--case-set` | 数据集：`all`（默认）、`l1`、`l2` |
| `--baseline-model` | 基线模型（默认 `qwen3.7-max`） |

**输出**：总成本对比、节省率、策略分布、安全降级/风险降级案例。

### Finance：企业财务评测

```bash
ai-router benchmark --level finance --real-api
```

### Routing：路由 Ground Truth 评测

```bash
ai-router benchmark --level routing
ai-router benchmark --level routing --rerun   # 完整重跑
```

## 7. audit — 消费审计

**用途**：分析数据库中的消费记录，找出浪费模式和重度用户。

**不消耗 API，查询本地数据库。**

### 基本用法

```bash
ai-router audit
```

### 参数

| 参数 | 说明 |
|------|------|
| `--days`, `-d` | 审计时间范围（默认 30 天） |
| `--user` | 按用户过滤 |
| `--project` | 按项目过滤 |
| `--department` | 按部门过滤 |
| `--db` | 数据库 URL（默认 `sqlite:///seed.db`） |
| `--format`, `-f` | 输出格式 |

### 示例

```bash
# 默认审计最近 30 天
ai-router audit

# 审计指定用户
ai-router audit --user alice --days 7

# 审计指定部门
ai-router audit --department engineering --days 90

# JSON 输出
ai-router audit --format json
```

### 输出内容

- **汇总**：总成本、总调用次数、日均消费、总 Token 数
- **按用户/模型/项目/部门**：多维度的成本分布表
- **浪费模式**：Top 5 浪费模式及改进建议
- **重度用户**：消费超过总成本 30% 的用户

## 8. run — 单次 Agent 执行

**用途**：启动 Agent 自主完成开发任务（读文件、改文件、跑测试）。

### 基本用法

```bash
# 先 dry-run 看看分析结果
ai-router run "修复 auth.py 中的 SQL 注入漏洞" --workdir demo/scenario1-sql-inject --dry-run

# 确认没问题，真实执行
ai-router run "修复 auth.py 中的 SQL 注入漏洞" --workdir demo/scenario1-sql-inject --yes
```

### 参数

| 参数 | 说明 |
|------|------|
| `task` | （必填）任务描述 |
| `--workdir`, `-w` | 工作目录（默认当前目录） |
| `--dry-run` | 只分析不执行 |
| `--max-cost` | 成本上限，单位元（默认 1.0） |
| `--max-turns` | 最大工具调用轮数（默认 10） |
| `--yes`, `-y` | 跳过人工确认 |
| `--format`, `-f` | 输出格式 |

### 执行流程

1. **路由分析**：分析任务 → 选策略 → 选模型
2. **人工审批**（如果风险高且没加 `--yes`）：展示任务详情，等待 `y/N` 确认
3. **Agent 执行**：
   - 模型通过工具（read_file / write_file / edit_file / run_command）自主完成
   - 每轮：模型思考 → 调用工具 → 看结果 → 继续
   - 直到任务完成、成本超限、或达到最大轮次
4. **输出报告**：成本、Token 用量、节省率、工具调用历史

### 安全机制

- **路径沙箱**：文件操作不能超出 `--workdir` 目录
- **命令白名单**：只允许 pytest / ruff / git status / git log / git diff / ls / wc / head / tail
- **危险模式拦截**：rm -rf / sudo / chmod 777 / git push --force 等被拦截
- **成本上限**：超过 `--max-cost` 自动停止

### Agent 能用的工具

| 工具 | 说明 | 什么时候可用 |
|------|------|-------------|
| `read_file` | 读取文件 | 始终可用 |
| `edit_file` | 精确替换文本 | 始终可用 |
| `run_command` | 执行命令 | 工程任务可用；支持受控的脚手架、依赖安装、测试、lint、构建、类型检查和只读诊断，删除及高危命令仍禁止 |
| `write_file` | 创建/覆盖文件 | 代码生成/重构/测试生成任务 |

### 执行策略

| 策略 | 说明 | 何时触发 |
|------|------|---------|
| `SINGLE_MODEL` | 单模型独立完成 | 大多数任务（系统智能选择） |
| `PLAN_EXECUTE` | Planner 规划 + Executor 执行 | 复杂任务且 PE 成本更优时 |
| `PLAN_EXECUTE_REVIEW` | 上述 + Reviewer 审查 | 高风险复杂任务 |

## 9. agent — 交互式 Agent

**用途**：启动交互式 REPL 会话，支持多轮对话、追问、迭代修改。类似 Claude Code 的使用体验。

**与 `run` 的区别**：`run` 是一次性任务执行器（输入任务 → 执行 → 结束）；`agent` 是持续会话（输入任务 → 执行 → 看结果 → 继续追问/追加修改）。

### 基本用法

```bash
# 启动交互式会话
ai-router agent --workdir demo/scenario1-sql-inject

# 进入 REPL 后输入任务
> 帮我修复 auth.py 里的 SQL 注入

# 多轮对话
> 解释一下你改了什么
> 再跑一下测试确认

# 使用 slash 命令
/cost          # 查看会话成本
/files         # 查看已修改的文件
/model         # 打开模型列表，输入编号直接选择
/exit          # 退出并保存会话
```

### 参数

| 参数 | 说明 |
|------|------|
| `--workdir`, `-w` | 工作目录（默认当前目录） |
| `--model`, `-m` | 覆盖路由推荐的模型 |
| `--yes`, `-y` | 跳过所有确认（包括首轮模型确认和高风险确认） |
| `--max-cost` | 会话总成本上限，单位元（默认 5.0） |
| `--max-turns` | 每轮最大工具调用次数（默认 30） |
| `--resume` | 恢复会话：`latest` 或 session_id |

### Slash 命令

| 命令 | 说明 |
|------|------|
| `/help` | 显示所有命令 |
| `/model` | 显示全部候选模型，输入编号直接选择 |
| `/model <名称>` | 按名称切换模型（如 `/model deepseek-v4-pro`） |
| `/model auto` | 取消手动指定，恢复 OpenSquilla + Router 智能选模 |
| `/cost` | 查看会话累积成本 |
| `/files` | 查看本会话修改的文件 |
| `/summary` | 查看上下文摘要 |
| `/compact` | 手动压缩上下文 |
| `/reset` | 清空对话上下文（成本/文件历史保留） |
| `/exit` | 退出并保存会话 |

### 会话持久化

每次执行完一轮后自动保存到 `.airouter/sessions/<session_id>/`：

| 文件 | 内容 |
|------|------|
| `session.json` | 元数据（workdir、model、turn_count 等） |
| `messages.current.json` | 对话历史（不含 system prompt） |
| `events.jsonl` | 审计日志（每轮一条） |
| `tools.jsonl` | 工具调用记录 |
| `cost.json` | 累积成本 |
| `touched_files.json` | 被修改的文件列表 |

### 会话恢复

```bash
# 恢复最近一次会话
ai-router agent --resume latest

# 恢复指定会话
ai-router agent --resume 20260618_102250_455713
```

恢复后可以继续对话，上下文和成本都会续接。

### 首轮模型确认

首次输入任务时，系统会展示路由分析结果并询问是否使用推荐的模型：

```
路由推荐模型: deepseek-v4-flash  |  预估成本: ¥0.0012
使用此模型执行？ [Y/n]:
```

- 按 Enter（默认 Y）→ 执行
- 输入 n → 取消，用 `/model` 切换后重试
- `--yes` 跳过此确认

### 上下文压缩

对话历史超过阈值时自动压缩（保留最近 4 轮完整对话 + 旧轮次的摘要）。也可手动执行 `/compact`。

压缩会优先调用已配置的轻量模型生成摘要，因此会消耗少量 Token 并计入当前会话成本；如果没有可用的轻量模型，则退化为本地截断摘要。

### 交互式策略限制

交互式 `agent` 会正常使用 OpenSquilla 和 Router 分析每一轮任务，但当前 REPL 只使用一个执行模型持续对话。若 Router 推荐 `PLAN_EXECUTE` 或 `PLAN_EXECUTE_REVIEW`，终端会提示该建议，但本轮仍由执行模型按单模型循环完成。

需要真实 Planner → Executor → Reviewer 多模型协作时，请使用一次性的 `ai-router run`。

### 安全机制

与 `run` 相同：路径沙箱、命令白名单（`pytest`/`ruff`/`git`/`ls`/`find`/`wc`/`head`/`tail`）、危险模式拦截、成本上限。

## 10. Demo 演示流程

项目包含 4 个预置 demo 场景，在 `demo/` 目录下。

### 准备

```bash
# 恢复所有 demo 到初始状态
python demo/reset_scenarios.py
```

## 11. 常见问题

### Q: 运行 `ai-router` 提示 command not found？

确保已安装并激活虚拟环境：

```bash
source .venv/bin/activate
pip install -e .
```

### Q: 运行 `run --yes` 报 API 错误？

检查 `.env` 文件是否存在且包含有效的 API Key。Key 格式：`AIROUTER_DEEPSEEK_API_KEY=sk-xxxx`。

### Q: sklearn 版本警告？

正常现象（OpenSquilla ML 模型的 pickle 版本差异），不影响功能。程序已自动静默该警告。

### Q: Agent 执行后文件没变化？

- 检查 `--workdir` 是否正确指向 demo 目录
- 检查工具调用历史中是否有 FAIL
- 某些模型（如 flash 版本）在输出大段代码时可能 JSON 格式出错

### Q: 为什么系统选择 SINGLE_MODEL 而不是 Plan-Execute？

这是智能路由的设计特性。系统会根据成本-质量评分选择最优策略。当 Tier 1 模型（如 deepseek-v4-pro）性价比足够高时，单模型反而比 Planner+Executor 组合更优。Plan-Execute 会在 Tier 1 模型更贵、任务更复杂时自动触发。

### Q: 一次 Agent 执行大概花多少钱？

现有 demo 实测通常约 ¥0.01-0.05，部分任务相对最贵 Tier 1 基线可节省 80-95%。这只是演示数据，实际费用和节省率取决于所选模型、上下文长度、工具轮次及是否触发摘要压缩。

### Q: `agent` 和 `run` 该用哪个？

- **`run`**：任务明确、一次完成。适合"修复这个 bug"、"生成这个函数"等单一任务。
- **`agent`**：需要迭代、追问、多步修改。适合"帮我重构这个模块"、"先看看代码，再决定怎么改"等探索性任务。

### Q: `agent` 会话中断了怎么办？

```bash
# 恢复最近会话（上下文、成本都会续接）
ai-router agent --resume latest
```

会话自动保存在 `.airouter/sessions/` 目录下，每轮执行后都会持久化。

### Q: `agent` 里第一个工具调用显示 `✗ run_command({})`？

这是 flash 模型偶尔输出空参数的 function call，被安全机制拦截。模型会在下一轮自动恢复，不影响最终结果。如需避免，可用 `--model deepseek-v4-pro` 切换到更稳定的模型。
